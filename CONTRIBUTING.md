# Contributing

Thanks for considering a contribution.

## Before you start

Please discuss any proposed change via a GitHub Issue first.

- Open an issue describing the problem/opportunity and your proposed approach.
- Wait for a maintainer to confirm the approach before starting significant work.
- For larger changes, we may ask for a short design note in the issue.

This helps avoid duplicated effort and ensures we’re aligned on UX, scope, and sequencing.

## Development setup

We keep setup and day-to-day commands in the project README. Please follow the **Developer Documentation** section there.

## Pull request guidelines

### Quality bar

- Keep changes focused and small where possible.
- Ensure changes are documented where appropriate (user-facing behaviour in docs/specs, developer notes when needed).
- Run formatting + linting and fix any warnings/errors before requesting review.
- Add tests where appropriate:
	- Bug fixes should include a regression test.
	- New behaviour should include unit/widget tests unless it’s impractical (explain why in the PR).

### Review notes

- Include clear steps for maintainers to follow to verify the change.
- Mention any trade-offs or follow-ups.

## IP and licensing

To keep ownership and licensing unambiguous for the Medicines for Children project, maintainers may require a signed contributor agreement (sometimes referred to as a Contributor License Agreement (CLA) or similar contributor covenant) before we can merge a contribution.

If this applies to your change, a maintainer will raise it in the Issue/PR.

## Reporting issues

Use the issue templates in `.github/ISSUE_TEMPLATE` and include steps to reproduce.

## Code of Conduct

By participating, you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md).
